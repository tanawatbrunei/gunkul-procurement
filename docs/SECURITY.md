# ความปลอดภัยของระบบ (Closed System)

ระบบนี้เป็น **ระบบปิด**: จะอ่าน/เขียนข้อมูลได้ต้อง (1) ล็อกอินด้วยอีเมลที่ **ยืนยันแล้ว** และ
(2) อีเมลนั้นอยู่ใน **รายชื่ออนุญาต** ที่ admin จัดการเองที่เมนู "จัดการผู้ใช้"
ตัวบังคับจริงคือ **Firestore Security Rules** (`firestore.rules`) ไม่ใช่หน้าเว็บ — หน้าเว็บแค่แสดงข้อความให้เข้าใจ

## ส่วนประกอบ
| อะไร | ที่ไหน |
|---|---|
| รายชื่ออนุญาต | Firestore `allowedUsers/{อีเมลตัวพิมพ์เล็ก}` → `{ email, role: "admin"\|"member", addedBy, addedAt }` |
| Admin หลัก (เข้าได้เสมอ) | `BOOTSTRAP_ADMIN_EMAILS` ใน `src/config/admins.ts` **และ** `isBootstrapAdmin()` ใน `firestore.rules` (ต้องแก้ 2 ที่ให้ตรงกัน) |
| หน้าจัดการ | `src/UsersPage.tsx` (เห็นเฉพาะ admin) — เพิ่มหลายอีเมล, ดึงจาก Staff Directory, เปลี่ยนสิทธิ์, ลบ |
| ตรวจสิทธิ์ฝั่งเว็บ | `src/access.tsx` + `src/components/AccessGate.tsx` (หน้ายืนยันอีเมล / ไม่ได้รับอนุญาต) |
| สิทธิ์ลบ Vendor | เฉพาะ admin (ทั้งปุ่มในเว็บและ rule) |

Apps Script ที่ sync Google Sheet ใช้สิทธิ์ IAM ของเจ้าของ Sheet (Cloud Datastore User) ซึ่งไม่ผ่าน Security Rules จึงไม่ถูกกระทบ

## ลำดับการเปิดใช้ครั้งแรก (ทำผิดลำดับ = ทีมเข้าไม่ได้)
Rules **ไม่ deploy พร้อมโค้ด** ต้อง Publish ใน Firebase Console เอง

1. Merge โค้ด → Vercel deploy (1–2 นาที) *ช่วงนี้สมาชิกที่ยังไม่อยู่ในรายชื่อจะเห็นหน้า "ยังไม่ได้รับอนุญาต" จนถึงข้อ 4*
2. **admin เข้าเว็บก่อน** → หน้า "ยืนยันอีเมลก่อนใช้งาน" → กดลิงก์ในอีเมล (Rules ใหม่ต้องการอีเมลที่ยืนยันแล้วแม้แต่ admin)
3. Firebase Console → Firestore → Rules → วางเนื้อหา `firestore.rules` ทั้งไฟล์ → **Publish**
4. เมนู **จัดการผู้ใช้** → "ดึงอีเมลจากรายชื่อพนักงาน" → ตรวจดู → "เพิ่มเข้ารายชื่อ"
5. แจ้งทีมให้เปิดเว็บ → กดลิงก์ยืนยันอีเมลที่ส่งให้ (ครั้งเดียว) → เข้าใช้งานได้

**ถอยกลับ:** Console → Firestore → Rules → ประวัติ (History) → เลือกเวอร์ชันก่อนหน้า → Publish

## งานประจำ
- **คนใหม่:** admin เพิ่มอีเมลในหน้าจัดการผู้ใช้ → คนนั้นสมัคร/ล็อกอิน → ยืนยันอีเมลครั้งแรก
- **คนลาออก:** ลบอีเมลออกจากรายชื่อ (ตัดสิทธิ์ตั้งแต่คำขอถัดไป) และควรปิดบัญชีที่ Firebase Console → Authentication ด้วย
- **เพิ่ม/ลด admin หลัก:** แก้ `src/config/admins.ts` + `isBootstrapAdmin()` ใน `firestore.rules` แล้ว Publish ใหม่

## สิ่งที่ยังเป็นความเสี่ยง (ตั้งใจไม่ทำในรอบนี้)
- API key ของ Firebase เป็นข้อมูลสาธารณะตามการออกแบบ ควรจำกัดโดเมนที่ใช้ได้ใน Google Cloud Console → Credentials
- การสมัครบัญชีเปิดอยู่ (คนนอกสร้างบัญชีได้แต่เข้าข้อมูลไม่ได้) ถ้ารำคาญ ปิดที่ Authentication → Settings → User actions
- ไม่มี MFA / SSO ระดับองค์กร (ต้องให้ IT ตั้งค่า)
- ไฟล์ที่เคยอยู่ใน `public/` (`vendor_master.json`, PDF ใน `documents/`) และ seed โครงการ ถูกลบออกจากเวอร์ชันปัจจุบันแล้ว
